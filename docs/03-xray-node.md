# ۰۳ — نود VPN

پنل **تک‌نودی** است: ترافیک مشتری‌ها از همان سروری رد می‌شود که خودِ پنل روی آن اجرا می‌شود.
سرویس `xray` در همان `compose.yaml` تعریف شده و پنل مستقیماً با `xray api` مدیریتش می‌کند —
بدون SSH، بدون کلید، بدون سرور دوم.

> ⚠️ **مهم:** نود باید به اینترنت آزاد دسترسی داشته باشد. یعنی این پنل باید روی
> سروری **خارج از کشور** نصب شود. اگر پنل را داخل ایران بالا بیاورید، کانفیگ‌ها
> ساخته می‌شوند ولی به کار مشتری نمی‌آیند.

---

## راه‌اندازی — یک دستور

```bash
docker compose exec app php artisan panel:setup-local-node \
    --address=203.0.113.10 \
    --port=443 \
    --sni=www.microsoft.com \
    --name="سرور اصلی" \
    --country=NL
```

این دستور:

1. جفت‌کلید **REALITY** می‌سازد (`xray x25519`)
2. یک `shortId` تصادفی تولید می‌کند
3. `docker/xray/config.json` را می‌نویسد — شامل بلوک‌های `api` + `stats` + `policy`
   که برای مدیریت کاربر و شمارش مصرف لازم‌اند
4. نود و اینباند `vless-reality` را در پنل ثبت می‌کند
5. `XRAY_PORT` را در `.env` تنظیم می‌کند
6. سرویس‌های فعالی که هنوز به نود وصل نبودند را وصل می‌کند

> **`--address` را با IP واقعی سرورتان پر کنید.** اگر متن نمونه را عیناً کپی کنید،
> دستور با خطا متوقف می‌شود. ساده‌تر: `--address` را اصلاً ندهید تا خودش IP عمومی
> سرور را پیدا کند.

سپس Xray را بالا بیاورید:

```bash
docker compose --profile vpn up -d xray
docker compose exec app php artisan panel:test-node
```

خروجی موفق:

```
نسخهٔ Xray: 26.x.x
+---------------+----------+------+
| tag           | protocol | port |
+---------------+----------+------+
| vless-reality | vless    | 443  |
+---------------+----------+------+
```

**تمام.** از این به بعد هر سرویسی که فروخته شود خودکار روی این نود ساخته می‌شود.

برای اینکه از این پس `docker compose up -d` خودش Xray را هم بالا بیاورد، به `.env` اضافه کنید:

```dotenv
COMPOSE_PROFILES=vpn
```

## گزینه‌های دستور

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `--address` | حدس خودکار IP عمومی | آدرسی که در کانفیگ مشتری می‌نشیند — **IP یا دامنهٔ واقعی**، نه متن نمونه |
| `--port` | `443` | پورت VLESS |
| `--sni` | `www.microsoft.com` | دامنهٔ پوششی REALITY |
| `--name` | `سرور اصلی` | نام نمایشی در پنل |
| `--country` | — | کد دو حرفی، برای قالب نام کانفیگ |
| `--force` | — | بازتولید کلیدها ⚠️ |

> `--force` همهٔ کانفیگ‌های فروخته‌شده را بی‌اعتبار می‌کند. فقط وقتی استفاده کنید
> که کلید لو رفته باشد — و بعدش به همهٔ مشتری‌ها لینک جدید بدهید.

## فایروال

```bash
ufw allow 22/tcp
ufw allow 443/tcp        # همان XRAY_PORT
ufw allow 80/tcp         # برای پنل و گواهی SSL
ufw --force enable
```

پورت API (`10085`) روی هاست publish **نمی‌شود** و فقط از داخل شبکهٔ داکر در دسترس است.

## تعارض پورت ۴۴۳

پنل و Xray هر دو نمی‌توانند ۴۴۳ را بگیرند:

| راه | پیکربندی |
|---|---|
| **ساده‌ترین** | Xray روی ۸۴۴۳ (`--port=8443`)، پنل روی ۴۴۳ |
| **REALITY روی ۴۴۳** | Xray روی ۴۴۳، پنل روی پورت دیگر (مثلاً ۲۰۹۶) |
| **حرفه‌ای** | Xray روی ۴۴۳ با `fallbacks` به nginx |

Xray برای پورت غیر ۴۴۳ هشدار می‌دهد (کمی بیشتر جلب توجه می‌کند) ولی در عمل کار می‌کند.

---

## انتخاب دامنهٔ پوششی

REALITY خودش را شبیه یک سایت واقعی نشان می‌دهد. دامنهٔ پوششی باید:

- TLS 1.3 و HTTP/2 داشته باشد
- **خارج از کشور شما** باشد
- **از خودِ نود سریع در دسترس باشد** — Xray برای هر اتصال با آن هندشیک می‌کند.
  اگر کند باشد، مشتری اصلاً وصل نمی‌شود.

تست سرعت از روی نود:

```bash
docker compose exec app sh -c 'time wget -qO- --spider https://www.microsoft.com'
```

گزینه‌های رایج: `www.microsoft.com` · `dl.google.com` · `www.cloudflare.com` · `www.lovelive-anime.jp`

## مدیریت از پنل

`مدیریت ← نود VPN`

| بخش | کار |
|---|---|
| کارت‌های وضعیت | آنلاین/بی‌پاسخ، تعداد سرویس، اینباند فعال، آخرین پاسخ |
| **تست اتصال** | بررسی اینکه Xray بالا است و اینباندهای `config.json` را نشان می‌دهد |
| **همگام‌سازی مجدد** | بازنویسی همهٔ کاربران فعال روی نود |
| تنظیمات نود | نام، آدرس، کشور، مسیرهای Xray، فعال/غیرفعال |
| اینباندها | افزودن، ویرایش و حذف |

> افزودن یا حذف **سرور** وجود ندارد — پنل تک‌نودی است.

### فیلدهای اینباند

`tag` باید **دقیقاً** با `tag` همان اینباند در `docker/xray/config.json` یکی باشد.

| فیلد | کِی لازم است |
|---|---|
| `Network` | `tcp` برای REALITY، `ws`/`grpc` برای پشت CDN |
| `Security` | `reality` توصیه‌شده؛ `tls` برای دامنهٔ دارای گواهی |
| `SNI` | دامنهٔ پوششی REALITY یا دامنهٔ گواهی TLS |
| `Flow` | فقط `vless` + `tcp`؛ مقدار `xtls-rprx-vision` |
| `pbk` / `sid` / `spx` | فقط برای REALITY |
| `Path` / `Host` | برای `ws` و `xhttp` |
| `serviceName` | برای `grpc` |

**قالب نام کانفیگ** تعیین می‌کند مشتری در کلاینت چه اسمی ببیند.
متغیرها: `{brand}` `{server}` `{country}` `{protocol}` `{plan}` `{tag}` `{user}`

## افزودن اینباند دوم (اختیاری)

مثلاً VMess روی WebSocket برای مشتری‌هایی که REALITY برایشان کار نمی‌کند.

**۱ — به `docker/xray/config.json` اضافه کنید:**

```json
{
  "tag": "vmess-ws",
  "listen": "0.0.0.0",
  "port": 8081,
  "protocol": "vmess",
  "settings": { "clients": [] },
  "streamSettings": {
    "network": "ws",
    "wsSettings": { "path": "/ray" }
  },
  "sniffing": { "enabled": true, "destOverride": ["http", "tls"] }
}
```

**۲ — پورت را در `compose.yaml` به سرویس `xray` اضافه کنید:**

```yaml
    ports:
      - "${XRAY_PORT:-443}:${XRAY_PORT:-443}"
      - "8081:8081"
```

**۳ — Xray را ری‌استارت کنید:**

```bash
docker compose --profile vpn up -d xray
```

**۴ — در `مدیریت ← نود VPN ← + افزودن اینباند`** همان اینباند را با `tag=vmess-ws`،
`protocol=vmess`، `port=8081`، `network=ws`، `path=/ray` ثبت کنید.

**۵ — «همگام‌سازی مجدد» بزنید** تا کاربران روی اینباند جدید هم ساخته شوند.

> Trojan و gRPC هم به همین شکل. هر سه پروتکل تست شده‌اند.

## نکات نگه‌داری

**کاربران فقط در حافظهٔ Xray هستند.** با هر ری‌استارت پاک می‌شوند. زمان‌بند هر
۱۰ دقیقه با `panel:heal-nodes` بررسی و ترمیم می‌کند، ولی می‌توانید فوراً هم بزنید:

```bash
docker compose exec app php artisan panel:heal-nodes
```

**بعد از هر تغییر در `config.json`:**

```bash
docker compose --profile vpn up -d xray
docker compose exec app php artisan panel:sync-node
```

**از `docker/xray/config.json` بکاپ بگیرید** — کلید خصوصی REALITY آنجاست.
این فایل در `.gitignore` است و نباید وارد مخزن شود.

## عیب‌یابی

| پیام | علت | راه‌حل |
|---|---|---|
| `سرویس Xray پاسخ نداد` | کانتینر xray بالا نیست | `docker compose --profile vpn up -d xray` |
| `failed to load config` | `config.json` خراب است | `panel:setup-local-node` را دوباره اجرا کنید |
| `اینباند «X» روی نود وجود ندارد` | `tag` پنل با `tag` نود یکی نیست | هر دو را مقایسه کنید |
| `Added 0 user(s)` | `port` یا `tag` اینباند در پنل غلط است | فرم اینباند را با `config.json` تطبیق دهید |
| مصرف همیشه صفر | بلوک `policy`/`stats` در config نیست | `panel:setup-local-node` بازسازی می‌کند |
| مشتری وصل نمی‌شود | دامنهٔ پوششی از نود کند است | `--sni` را عوض کنید |

```bash
docker compose exec app php artisan panel:test-node   # تشخیص سریع
docker compose logs xray --tail 30                    # لاگ خود Xray
```
